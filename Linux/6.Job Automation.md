# Job Automation

## Automation with `cron` and `at`

- In any operating system, it is possible to create jobs that you want to reoccur. This process, known as **job scheduling**, is usually done based on user-defined jobs.
- For Red Hat or other Linux distributions, this process is handled by the cron service or a daemon called `cron`, which can be used to schedule tasks (also called jobs).
- By default, Red Hat comes with a set of predefined jobs that occur on the system (hourly, daily, weekly, monthly, and with arbitrary periodicity). As an administrator, however, you can define your own jobs and allow users to create them as well.

### Importance of Job Scheduling
- Critical tasks like taking backups, which usually need to occur at night, can easily be performed without manual intervention by scheduling a cron job.
- For example, if a cron job is scheduled carefully, the backup will be taken at any given time of the client, and there will be no need for the administrator to remain back at nights to take the backup.

### Important Files Related to `cron` and `at`

- `/etc/crontab`: File where all scheduled jobs are stored.
- `/etc/cron.deny`: File used to restrict users from using cron jobs.
- `/etc/cron.allow`: File used to allow only users whose names are mentioned to use cron jobs (this file does not exist by default).
- `/etc/at.deny`: Same as `cron.deny`, for restricting `at` jobs.
- `/etc/at.allow`: Same as `cron.allow`, for allowing users to use `at` jobs.

### Crontab Format
To assign a job in the crontab file, the format used is as follows:

```
minute (0-59)
hour (0-23)
day of month (1-31)
month (1-12) OR jan,feb,mar,apr...
day of week (0-6) (Sunday=0 or 7) OR sun,mon,tue,wed,thu,fri,sat
command to be executed
```

### Options
| Option      | Explanation                                                                                       |
|-------------|---------------------------------------------------------------------------------------------------|
| `*`         | Treated as a wildcard, meaning any possible value.                                                |
| `*/5`       | Treated as every 5 minutes, hours, days, or months. Replacing 5 with another numerical value changes this. |
| `2,4,6`     | Treated as an OR. In hours, this could mean at 2, 4, or 6 o'clock.                                |
| `9-17`      | Treated as any value between 9 and 17. For days, this means between the 9th and 17th.             |

### Crontab Commands

| Command    | Explanation                                                                                        |
|------------|----------------------------------------------------------------------------------------------------|
| `crontab -e` | Edit your crontab file or create one if it doesn’t already exist.                                  |
| `crontab -l` | Display your crontab file.                                                                       |
| `crontab -r` | Remove your crontab file.                                                                        |
| `crontab -u` | If combined with `-e`, edit another user’s crontab file. If combined with `-l`, display theirs.    |

## Lab Work

### CRON JOBS

- **To check the assigned cron jobs of the currently logged-in user:**
  ```
  crontab -l
  ```

- **To check the cron jobs of a particular user:**
  ```
  crontab -l -u <username>
  ```

### Example Jobs

1. **Display the Current Date Every Minute:**
   - Identify the active console:
     ```
     tty
     ```
   - Output (e.g., `/dev/pts/1`) is used in the following:
     ```
     * * * * * date > /dev/pts/1
     ```
   - Restart cron service:
     ```
     service crond restart
     ```

2. **Run a Backup Script (`bkpscript.sh`) Every Saturday at 12:30 PM:**
   ```bash
   chmod +x bkpscript.sh
   crontab -e
   30 12 * * 6 /path/to/bkpscript.sh
   service crond restart
   ```

3. **Create a Directory on a Specific Date:**
   - Example: Create `/root/ktdir` on "Sunday, October 22, 1:30 AM":
     ```bash
     30 1 22 10 7 mkdir /root/ktdir
     ```

4. **Send Emails on Specific Dates:**
   - Example: Notify `ktuser` of meetings:
     ```bash
     crontab -e -u ktuser
     25 14 27,29,31 10 * echo "Meeting at 3:00 PM Today"
     ```

  ktuser
