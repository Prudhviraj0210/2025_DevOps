# SSH Guide for Automation and Management

## Introduction to SSH

- **SSH (Secure Shell)** is a protocol used to securely access remote systems over an unsecured network.
- SSH enables encrypted communication between a client and a server.
- It is commonly used for:
  - Remote login
  - Command execution
  - File transfer (with tools like `scp` or `rsync`)

### Key Features of SSH
- **Encryption**: Ensures data privacy and integrity.
- **Authentication**: Supports password-based and key-based authentication.
- **Port Forwarding**: Enables tunneling of data securely.
- **File Transfer**: Use `scp` or `sftp` for secure file transfers.

## Setting Up SSH

### Installing SSH
- **Check if SSH is installed**:
  ```bash
  ssh -V
  ```
- **To install SSH server and client** (if not already installed):
  - On Red Hat-based systems (e.g., CentOS, Fedora):
    ```bash
    sudo yum install openssh-server openssh-clients
    ```
  - On Debian-based systems (e.g., Ubuntu):
    ```bash
    sudo apt-get install openssh-server openssh-client
    ```

### Starting and Enabling SSH Service
- **Start the SSH service**:
  ```bash
  sudo systemctl start sshd
  ```
- **Enable the SSH service to start on boot**:
  ```bash
  sudo systemctl enable sshd
  ```
- **Check the status of the SSH service**:
  ```bash
  sudo systemctl status sshd
  ```

## Configuring SSH

### SSH Configuration File
- The main configuration file is located at:
  ```
  /etc/ssh/sshd_config
  ```
- Common configurations to modify:
  | Parameter           | Description                                         |
  |---------------------|-----------------------------------------------------|
  | `Port`              | The port SSH listens on (default is `22`).          |
  | `PermitRootLogin`   | Controls whether root login is allowed.             |
  | `PasswordAuthentication` | Enable or disable password-based authentication.|
  | `AllowUsers`        | Specify which users can log in via SSH.             |

### Applying Configuration Changes
- After making changes to `sshd_config`, restart the SSH service:
  ```bash
  sudo systemctl restart sshd
  ```

## SSH Authentication Methods

### Password-Based Authentication
- Default method.
- Users log in with their system username and password.
- To enable/disable, modify:
  ```
  PasswordAuthentication yes
  ```

### Key-Based Authentication
- A more secure alternative to passwords.
- **Generate an SSH key pair** (on the client):
  ```bash
  ssh-keygen -t rsa -b 4096 -C "your_email@example.com"
  ```
- **Copy the public key to the server**:
  ```bash
  ssh-copy-id user@server
  ```
- Alternatively, manually copy `~/.ssh/id_rsa.pub` to `~/.ssh/authorized_keys` on the server.
- **Disable password authentication for better security**:
  ```
  PasswordAuthentication no
  ```

## SSH Commands

### Common SSH Commands
| Command                        | Description                                   |
|--------------------------------|-----------------------------------------------|
| `ssh user@server`              | Connect to a remote server.                  |
| `ssh -p 2222 user@server`      | Connect to a server on a custom port (e.g., 2222). |
| `scp file user@server:/path`   | Copy a file to a remote server.               |
| `scp user@server:/path file`   | Copy a file from a remote server.             |
| `rsync -avz file user@server:/path` | Sync files to a remote server.              |
| `ssh -L local_port:remote_host:remote_port user@server` | Create an SSH tunnel. |

## Hardening SSH Security

### Key Recommendations
1. **Change Default Port**:
   - Edit `/etc/ssh/sshd_config`:
     ```
     Port 2222
     ```
   - Restart SSH:
     ```bash
     sudo systemctl restart sshd
     ```

2. **Disable Root Login**:
   - In `/etc/ssh/sshd_config`:
     ```
     PermitRootLogin no
     ```
   - Restart SSH.

3. **Disable Password Authentication**:
   - Use key-based authentication and set:
     ```
     PasswordAuthentication no
     ```

4. **Allow Specific Users**:
   - In `/etc/ssh/sshd_config`:
     ```
     AllowUsers user1 user2
     ```

5. **Use Fail2Ban**:
   - Install Fail2Ban to block IPs with repeated failed login attempts.
     ```bash
     sudo yum install fail2ban
     ```

## Automating with SSH

### Running Remote Commands
- **Single Command**:
  ```bash
  ssh user@server "command"
  ```
- **Multiple Commands**:
  ```bash
  ssh user@server << EOF
  command1
  command2
  EOF
  ```

### Automating with Scripts
- Example: Batch file transfer using `scp`:
  ```bash
  #!/bin/bash
  for server in server1 server2 server3; do
      scp /path/to/file user@$server:/remote/path
  done
  ```

## Troubleshooting SSH

### Check SSH Logs
- **On the server**:
  ```bash
  sudo tail -f /var/log/secure
  ```

### Debugging SSH Connections
- Use the `-v` option for verbose output:
  ```bash
  ssh -v user@server
  ```
- Increase verbosity with `-vv` or `-vvv`.

### Common Issues
| Issue                        | Solution                                       |
|------------------------------|-----------------------------------------------|
| Connection refused           | Check if SSH is running and listening on the correct port. |
| Permission denied            | Verify credentials or key pair configuration. |
| Host key verification failed | Remove the old host key from `~/.ssh/known_hosts`. |
