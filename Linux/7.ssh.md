# SSH Guide for Automation and Management

## Introduction to SSH

- **SSH (Secure Shell)** is a protocol used to securely access remote systems over an unsecured network.
- SSH enables encrypted communication between a client and a server.
- It is commonly used for:
  - Remote login
  - Command execution
  - File transfer (with tools like `scp` or `rsync`)

### Key Features of SSH
- **Encryption**: Ensures data privacy and integrity.
- **Authentication**: Supports password-based and key-based authentication.
- **Port Forwarding**: Enables tunneling of data securely.
- **File Transfer**: Use `scp` or `sftp` for secure file transfers.

---

## Setting Up SSH

### Installing SSH
- **Check if SSH is installed**:
  ```bash
  ssh -V
  ```
- **To install SSH server and client** (if not already installed):
  - On Red Hat-based systems (e.g., CentOS, Fedora):
    ```bash
    sudo yum install openssh-server openssh-clients
    ```
  - On Debian-based systems (e.g., Ubuntu):
    ```bash
    sudo apt-get install openssh-server openssh-client
    ```

### Starting and Enabling SSH Service
- **Start the SSH service**:
  ```bash
  sudo systemctl start sshd
  ```
- **Enable the SSH service to start on boot**:
  ```bash
  sudo systemctl enable sshd
  ```
- **Check the status of the SSH service**:
  ```bash
  sudo systemctl status sshd
  ```

---

## Configuring SSH

### SSH Configuration File
- The main configuration file is located at:
  ```
  /etc/ssh/sshd_config
  ```
- Common configurations to modify:
  | Parameter           | Description                                         |
  |---------------------|-----------------------------------------------------|
  | `Port`              | The port SSH listens on (default is `22`).          |
  | `PermitRootLogin`   | Controls whether root login is allowed.             |
  | `PasswordAuthentication` | Enable or disable password-based authentication.|
  | `AllowUsers`        | Specify which users can log in via SSH.             |

### Applying Configuration Changes
- After making changes to `sshd_config`, restart the SSH service:
  ```bash
  sudo systemctl restart sshd
  ```

---

## SSH Authentication Methods

### Password-Based Authentication
- Default method.
- Users log in with their system username and password.
- To enable/disable, modify:
  ```
  PasswordAuthentication yes
  ```

### Key-Based Authentication
- A more secure alternative to passwords.
- **Generate an SSH key pair** (on the client):
  ```bash
  ssh-keygen -t rsa -b 4096 -C "your_email@example.com"
  ```
- **Copy the public key to the server**:
  ```bash
  ssh-copy-id user@server
  ```
- Alternatively, manually copy `~/.ssh/id_rsa.pub` to `~/.ssh/authorized_keys` on the server.
- **Disable password authentication for better security**:
  ```
  PasswordAuthentication no
  ```

## SSH Commands

### Common SSH Commands
| Command                        | Description                                   |
|--------------------------------|-----------------------------------------------|
| `ssh user@server`              | Connect to a remote server.                  |
| `ssh -p 2222 user@server`      | Connect to a server on a custom port (e.g., 2222). |
| `scp file user@server:/path`   | Copy a file to a remote server.               |
| `scp user@server:/path file`   | Copy a file from a remote server.             |
| `rsync -avz file user@server:/path` | Sync files to a remote server.              |
| `ssh -L local_port:remote_host:remote_port user@server` | Create an SSH tunnel. |

## Hardening SSH Security

### Key Recommendations
1. **Change Default Port**:
   - Edit `/etc/ssh/sshd_config`:
     ```
     Port 2222
     ```
   - Restart SSH:
     ```bash
     sudo systemctl restart sshd
     ```

2. **Disable Root Login**:
   - In `/etc/ssh/sshd_config`:
     ```
     PermitRootLogin no
     ```
   - Restart SSH.

3. **Disable Password Authentication**:
   - Use key-based authentication and set:
     ```
     PasswordAuthentication no
     ```

4. **Allow Specific Users**:
   - In `/etc/ssh/sshd_config`:
     ```
     AllowUsers user1 user2
     ```

5. **Use Fail2Ban**:
   - Install Fail2Ban to block IPs with repeated failed login attempts.
     ```bash
     sudo yum install fail2ban
     ```

## Automating with SSH

### Running Remote Commands
- **Single Command**:
  ```bash
  ssh user@server "command"
  ```
- **Multiple Commands**:
  ```bash
  ssh user@server << EOF
  command1
  command2
  EOF
  ```

### Automating with Scripts
- Example: Batch file transfer using `scp`:
  ```bash
  #!/bin/bash
  for server in server1 server2 server3; do
      scp /path/to/file user@$server:/remote/path
  done
  ```

## Troubleshooting SSH

### Check SSH Logs
- **On the server**:
  ```bash
  sudo tail -f /var/log/secure
  ```

### Debugging SSH Connections
- Use the `-v` option for verbose output:
  ```bash
  ssh -v user@server
  ```
- Increase verbosity with `-vv` or `-vvv`.

### Common Issues
| Issue                        | Solution                                       |
|------------------------------|-----------------------------------------------|
| Connection refused           | Check if SSH is running and listening on the correct port. |
| Permission denied            | Verify credentials or key pair configuration. |
| Host key verification failed | Remove the old host key from `~/.ssh/known_hosts`. |

  <summary> SSH Tunneling with `-L`</summary>
  ## Purpose of the Command
The `-L` option in SSH is used to create a **local port forwarding** tunnel. This allows you to forward traffic from a local port on your machine to a specific remote port on a remote machine through the SSH server (`user@server`).

---

## Command Breakdown
```bash
ssh -L local_port:remote_host:remote_port user@server
```
- `ssh`: Starts the SSH session.
- `-L`: Specifies that you are creating a local port forwarding tunnel.
- `local_port`: The port on your local machine that will listen for incoming connections.
- `remote_host`: The hostname or IP address of the destination machine on the remote network.
- `remote_port`: The port number on the remote machine where traffic will be forwarded.
- `user`: The username used to log in to the SSH server.
- `server`: The hostname or IP address of the SSH server you’re connecting to.

## Example Use Case
### Scenario: Accessing a Remote Database
You need to access a MySQL database running on `dbserver.example.com:3306` from your local machine. However, the database is behind a firewall and accessible only through the SSH server `bastion.example.com`.

### Command
```bash
ssh -L 3307:dbserver.example.com:3306 user@bastion.example.com
```

### What Happens?
1. **Local Port (3307)**: Your local machine listens on port 3307.
2. **Remote Host (dbserver.example.com)**: The remote MySQL server's address.
3. **Remote Port (3306)**: The port on which the MySQL server is running.
4. **SSH Server (bastion.example.com)**: The intermediary server forwarding traffic.

Now, you can connect to the MySQL database using:
```bash
mysql -h 127.0.0.1 -P 3307 -u username -p
```

## Additional Tips
### Using `autossh` for Persistent Tunnels
If the tunnel gets disconnected, you can use `autossh` to automatically reconnect:
```bash
autossh -L 3307:dbserver.example.com:3306 user@bastion.example.com
```

### Background the SSH Tunnel
Run the tunnel in the background using:
```bash
ssh -f -N -L 3307:dbserver.example.com:3306 user@bastion.example.com
```
- `-f`: Runs SSH in the background after authentication.
- `-N`: Specifies no remote command execution, just port forwarding.

### Multiple Tunnels
You can set up multiple tunnels by adding more `-L` options:
```bash
ssh -L 3307:dbserver.example.com:3306 -L 8080:webserver.example.com:80 user@bastion.example.com
```

## Troubleshooting
### Port Already in Use
If `local_port` is already in use, you’ll get an error. Choose a different port:
```bash
ssh -L 3308:dbserver.example.com:3306 user@bastion.example.com
```

### Connection Refused
- Check if the SSH server allows port forwarding (`AllowTcpForwarding` should be `yes` in `/etc/ssh/sshd_config` on the bastion server).
- Verify the remote service is listening on `remote_port`.

### Firewall Issues
Ensure firewalls on the bastion server and local machine allow the specified ports.
